# ir-core-lab

国产红外探测器**机芯（core）**嵌入式软件链路的**数值仿真原型**：从探测器原始响应 → 非均匀性校正 → 盲元处理 → 动态范围压缩/图像增强 → 帧输出，外加 **TEC 温控环**与 **VCSEL 恒流驱动**。

**纯 C99，零第三方依赖**（只用 libc + libm），`make test` 一键跑完全部自检，`make sim` 一键跑完端到端仿真并输出 `results/` 下的 CSV 与指标文本。

![ci](https://github.com/meminehobe24435-cmyk/ir-core-lab/actions/workflows/ci.yml/badge.svg)

---

## 为什么做

红外机芯的软件链路有个特点：**每一级处理都有明确的量化指标，而且这些指标之间有耦合**。TEC 稳不住温度，非均匀性校正的标定系数就会漂；盲元不剔除，会污染两点校正的增益解；AGC 拉得越狠，小目标的对比度反而可能被背景噪声吃掉。想把这条链路讲清楚，光看框图没用，必须能算出来。

这个仓库就是把这套链路的**数值部分**完整写一遍：每个模块都有明确的公式、明确的参数含义、以及**跑出来的数字**。目标不是做一个产品，而是把"探测器原始响应 → 可用图像"这条链路上每一步的工程取舍，用可以复现的代码和可验证的数字表达出来。

顺带把两件在旁边但很关键的事也写了：TEC 温控（探测器冷平台的温度稳定度直接决定标定是否有效）和 VCSEL 恒流驱动（阈值电流 `Ith(T)` 的温度漂移是 VCSEL 驱动的核心问题）。

## 快速开始

```bash
# 编译
make                       # 生成 test_ir 与 sim_ir
# 自检（正常输出最后一行是 "<N> checks passed"）
make test
# 端到端仿真，结果写入 results/*.csv 与 results/metrics.txt
make sim
```

指定编译器（Windows/MSYS2 例）：

```bash
make CC=/d/msys2/ucrt64/bin/gcc.exe test
# 或者
make CC=clang
```

环境要求：任意 C99 编译器 + libm。CI 上验证过 gcc 与 clang、Linux 与 macOS；本地还用 MSYS2 UCRT64 gcc 15.2.0 和 GNU Make 3.80 跑过。

**关于 `-ffp-contract=off`**：Makefile 与 CI 里都有这个选项，而且是必须的。不加它，clang（以及较新的 gcc）可能把 `a*b+c` 融合成一条 FMA 指令，浮点末位会变，NUC / TEC 的浮点断言只会在 macOS 上挂掉。这种"只在某个平台挂"的 bug 很难查，所以直接从编译选项上掐掉。

## 目录结构

```
src/ir_lab.[ch]     公共设施：确定性 RNG（xorshift32 + Box-Muller）、统计量、NU 定义、二进制文件写出
src/tec_ctrl.[ch]   探测器 TEC 温控：数字 PID + 抗积分饱和 + 一阶惯性加纯滞后被控对象
src/nuc.[ch]        非均匀性校正：模拟探测器阵列、黑体两点校正、单点校正对比
src/badpix.[ch]     盲元检测（3σ）与替换（3×3 中值），含迭代 σ 裁剪对比
src/agc.[ch]        动态范围压缩：直方图、百分位线性拉伸、HEQ、平台直方图均衡(plateau)
src/frame.[ch]      BT.656 风格行/场时序状态机 + 串口定长帧协议（CRC-16/CCITT）
src/vcs_pwr.[ch]    VCSEL 恒流环（PI）+ Ith(T)/η(T) 温漂模型 + 三种功率稳定策略对比
src/main_sim.c      端到端仿真入口，打印并落盘全部关键指标
test/test_ir.c      自检测试，无框架依赖，失败返回非 0
results/            仿真输出（已提交，因为仿真完全确定性，可逐字节复现）
```

### 一点必须说清楚的读数

**AGC 那一行不是"平台均衡最好"。** 三个映射在同一场景上的表现是：

| 映射 | 全局 σ | 局部对比度 | 目标-背景对比度 | CNR（目标/背景噪声） |
|---|---|---|---|---|
| 线性拉伸 | 42.544 | 0.2026 | **55.86 %** | **11.615** |
| 平台均衡 plateau=1.0 | 52.734 | 0.2122 | 44.99 % | 6.926 |
| 全直方图均衡 HEQ | **73.588** | **0.2662** | 37.66 % | 3.641 |

**HEQ 把全局亮度和局部对比度拉得最高，但小目标的 CNR 反而从 11.890 掉到 3.641**——因为 97 % 的像素是背景，HEQ 把绝大部分输出灰阶分给了背景，小目标被压到很窄的一段；同时背景噪声被同比放大。平台均衡的价值不在于"白送一个更好的结果"，而在于它是一个**可调旋钮**：`plateau_frac` 从 0.25 扫到 3.0，结果从"接近线性拉伸（CNR 10.2）"平滑过渡到"等于 HEQ（CNR 3.64）"（见 `results/agc_plateau_sweep.csv`）。给什么场景配什么旋钮是设计决策，不是算法优劣。

**VCSEL 的 0.008 % 也不是"APC 神了"。** 那是**无噪声**收敛值，实际受限于 MPD 链路量化（1.2 µA LSB ≈ 0.048 % of 5 mW）。把 MPD 噪声算进去才是可引用的数字：**RMS 0.016 %、峰值 0.056 %**。前馈的 1.774 % 则是**线性拟合逼近指数 `Ith(T)` 的固有残差**，不是调参没调好——把扫温区间缩小残差就会变小，见 `results/vcs_power_sweep.csv`。

**TEC 的鲁棒性扫描里有一条"失败"记录**（`results/tec_robustness.csv`，Rth=1.2 K/W 那三行）：调节时间 −1（永不进入 ±0.1 K），稳态误差 9 K。这不是控制器坏了，是**执行器不够**：把 −20 ℃ 的冷平台维持在 25 ℃ 环境下需要 (25−(−20))/1.2 = **37.5 W**，而驱动器只有 30 W。同样的结论对 Rth ≤ 1.5 K/W 都成立。

## 各模块算法与参数

### 1. TEC 温控（`tec_ctrl.c`）

被控对象是一阶惯性 + 纯滞后（FOPDT）的冷平台热模型：

```
Cth · dT/dt = (Tamb − T)/Rth + u(t − θ)
τ = Rth · Cth = 2.0 K/W × 4.0 J/K = 8 s，  θ = 0.4 s，  u ∈ [−30, +30] W
```

连续部分用零阶保持的**解析解**推进：`T[k+1] = Tss + (T[k] − Tss)·exp(−dt/τ)`，`Tss = Tamb + Rth·u_delayed`。这样没有欧拉离散误差（dt=20 ms、τ=8 s 时欧拉每步约 1e-4 K，会污染"稳态误差"这个数）。纯滞后用输出环形缓冲实现。

控制器是**位置式 PID，微分作用在测量值上**（避免设定值跳变引起的微分冲击）：

```
e[k]  = SP − y[k]                    （|e| < 死区 时 e 置 0，同时冻结积分）
df[k] = y 的一阶滤波变化率           （Tf = Td/N）
u_raw = Kp·e + I − Kd·df
u     = clip(u_raw, u_min, u_max)
```

抗积分饱和三种模式可切换（`IR_TEC_AW_NONE` / `_CLAMP` / `_BACKCALC`）：

- **CLAMP（条件积分）**：当输出已经顶到轨、且误差方向还会把它继续推向该轨时，**不积分**。
- **BACKCALC（反算法）**：`I += Ki·e·dt + (u − u_raw)·dt/Tt`，`Tt = Ti`。

`Kp = 5.0 W/K` 来自 FOPDT 的 IMC 整定（λ = θ）；`Ki = 2.5 W/(K·s)` 则是在仿真上扫出来的——IMC 给的 0.625 W/(K·s) 在饱和退出时误差还有约 6 K（30 W / 5 W/K），后续用开环时间常数 8 s 慢慢爬，调节时间 39 s；提到 2.5 之后这个尾巴消失。扫参表在 `results/tec_gain_sweep.csv`。

**微分项默认给 0，这是有意的**：热敏电阻量化到 10 mK，对量化信号求微分会产生比 ±0.1 K 判据带更大的极限环（扫参表里 `Ki=6.0` 那一档已经出现 57 mK 峰峰极限环）。微分通路仍然实现了，并且在单元测试里用无噪声解析输入单独验证。

### 2. NUC 两点校正（`nuc.c`）

单像元辐射响应模型：

```
S_ij(φ) = O_ij + G_ij · φ · (1 + C_ij · x) + n_ij(t),   x = (φ − φ_ref)/φ_ref
```

`O_ij` 是偏置（暗电流、ROIC 失调），`G_ij` 是增益（响应率差异），两者在阵列上的离散度就是**固定图案噪声 FPN**；`C_ij` 是每个像元残留的二次非线性系数，代表两点校正**去不掉**的那部分。

非均匀性定义按红外行业的惯例，在**均匀场景**上评估（这样只剩空间结构）：

```
NU [%] = 100 · σ(S) / |mean(S)|        （σ 为总体标准差）
```

两点校正：在黑体低温点 φ_low 与高温点 φ_high 各采一帧，逐像元解线性方程：

```
a_ij = (φ_high − φ_low) / (S_H,ij − S_L,ij)
b_ij = φ_low − a_ij · S_L,ij          校正：S' = a_ij·S + b_ij
```

对模型的线性部分是**精确**的，任意场景都能恢复到 φ。单点校正 `S' = S − S_L,ij + φ_low` 只去偏置，增益误差随离标定点的距离线性增长——这就是为什么指标要在非标定点的 φ 上评估。

参数（FPA 模拟用，数量级取自公开文献的**典型值**）：增益离散 12 % RMS，偏置离散 6 counts，二次系数 0.02，时域噪声 0.6 counts，阵列 128×128，确定性种子。

### 3. 盲元检测与替换（`badpix.c`）

判据用像元的**响应率**（两帧黑体差分）`r_ij = S_H,ij − S_L,ij`：

```
|r_ij − μ| > k·σ        （k = 3）
```

关键在于 μ 和 σ 要从**含有盲元的阵列**里估出来。单次遍历让野值把 σ 抬高，窗口变宽，把边缘盲元藏进去（50 % 响应率的弱盲元距良元总体只有约 3.3σ，但被抬高的 σ 一盖就进去了）。所以实现了 **迭代 σ 裁剪**：

```
repeat
    μ, σ ← 只用未标记像元统计
    标记所有落在 [μ−kσ, μ+kσ] 之外的像元
until 没有新标记（或达到迭代上限）
```

`iterations = 1` 就是朴素单次遍历，所以这个改进是被**测出来**的，不是被断言的。另有一道硬保护：标记比例超过 `max_flagged_frac`（默认 20 %）立即中止——否则在近似均匀的阵列上窗口会一路往下走，把大半个阵列判成盲元。

替换：被标记像元取其 3×3 邻域内**有效**邻居的中值（不用均值，避免盲元成簇时被带偏）；邻居本身也被标记的排除；有效邻居少于 `min_valid` 就保留原值。邻域永远从**输入**图读取，不从正在写的输出图读取，因此结果与扫描顺序无关。

### 4. AGC 动态范围压缩（`agc.c`）

- **百分位线性拉伸**：`lo, hi` 取 1 % / 99 % 分位，线性映射到 `[0, 255]`。单调、保辐射关系，但一个热点会把其余场景压成几个灰阶。
- **HEQ**：`out[i] = 255 · cdf[i] / cdf[last]`。最大化输出熵/对比度，但在背景占主导的红外场景上会过度放大背景噪声、压缩小目标。
- **平台直方图均衡**：`T = plateau_frac · N / bins`；`h'[i] = min(h[i], T)`，超出的部分**均匀回填**到所有 bin，再对 `h'` 做均衡。把主导模态（背景）的增益封顶，小目标就能分到更多灰阶。

两个极限行为在测试里被断言：`plateau_frac → ∞` 时**逐位等于 HEQ**；`plateau_frac → 0`（T 钳到 1 count）时逼近线性拉伸。

对比度指标：全局 σ、RMS 对比度 σ/μ、局部对比度（3×3 窗口 σ/μ 的均值）、Michelson 与 Weber 目标-背景对比度，以及 **CNR = |μ_t − μ_b| / σ_b**——最后这个才是"人眼能不能看见"的判据：把目标对比度和背景噪声同比放大的映射，净收益是零。

### 5. 帧输出与时序（`frame.c`）

BT.656 风格的行/场时序状态机，逐像素时钟推进，输出 data enable / hsync / vsync 与光栅坐标，并统计有效像素数与行数：

| 配置 | 行结构 | 帧结构 | 总时钟 |
|---|---|---|---|
| 128×128 红外核心 | 128 有效 + 32 消隐 = 160 | 128 有效 + 16 消隐 = 144 行 | 160 × 144 = **23 040** |
| BT.656 625/50 参考 | 720 有效 + 144 消隐 = 864 | 576 有效 + 49 消隐 = 625 行 | 864 × 2 × 625 = **1 080 000**（27 MHz 下 40.000 ms） |

**诚实说明**：这里只复现了 BT.656 的**光栅结构**，没有 SAV/EAV 定时基准码、没有 F/V/H 位编码、没有 4:2:2 色度复用。

串口定长帧协议：

```
| 0xA5 | 0x5A | type | len_lo | len_hi | payload ... | crc_lo | crc_hi |
|<-- 5 字节帧头 -->|<-- len 字节 -->|<-- 2 字节 -->|
```

CRC 为 **CRC-16/CCITT-FALSE**（多项式 0x1021，初值 0xFFFF，不反转，不异或输出），覆盖范围是 `type + len + payload`（帧头魔数本身不保护，这也和多数链路层协议一致）。标准校验向量 `"123456789" → 0x29B1` 在测试里断言。

### 6. VCSEL 恒流驱动与温漂补偿（`vcs_pwr.c`）

器件模型：

```
Ith(T) = Ith_ref · exp((T − T_ref)/T0)      T0 = 65 K（阈值 45 K 翻倍）
η(T)   = η_ref · (1 + a·ΔT + b·ΔT²)          η(25)=1.000 W/A, η(70)=0.735 W/A
P(T,I) = p_floor + η(T)·(I − Ith(T))        I > Ith
```

三种功率稳定策略：

| 策略 | 做法 | 实测最大偏差 |
|---|---|---|
| 固定电流 | 25 ℃ 标定一次，永不变 | **41.109 %** |
| 温度前馈 | 固件存 Ith(T)/η(T) 的最小二乘线性拟合，`I_set(T) = Ith_fit(T) + (P_tgt − p_floor)/η_fit(T)` | **1.774 %** |
| 闭环 APC | 对监视光电二极管读数做 PI，微调 I_set | **0.008 %**（无噪声）/ 含 MPD 噪声 RMS **0.016 %** |

内环是 PI 恒流环，被控对象是一阶驱动模型（τ = 20 µs）加电流环 DAC 量化（15 mA/4096）。APC 外环按设计原则与内环分离**两个数量级以上**（外环 τ ≈ 1 ms）。

## 边界说明（如实声明）

**这是一个纯数值仿真项目。** 以下每一条都是字面意思，请按字面理解：

1. **没有真实红外探测器，没有真实硬件，没有 TEC 实物，没有 VCSEL 实物。** 全部数据由本仓库的代码计算得到，没有任何一部分来自实验台架或实测。
2. **探测器模型是简化模型**：线性响应 + 加性噪声（每个像元一个增益、一个偏置、一个二次项）。**不含 1/f 噪声、不含光子噪声的完整物理模型、不含真实器件的非线性与暗电流温度模型。** 温度对探测器的影响没有建模——TEC 模块和成像链路是两条独立的仿真线，没有串起来。
3. **参数取自公开文献的典型数量级，不是任何厂商器件的实测参数。** `Rth = 2.0 K/W`、`τ = 8 s`、`T0 = 65 K`、增益离散 12 % 等等，都是"量级对得上"的设定值，不是标定结果。仿真里的"黑体低温点/高温点"是数值，不是黑体炉。
4. **不是产品代码。** 全部在 PC 上编译运行，**没有跑在真实 MCU 上**（没有交叉编译、没有链接脚本、没有启动代码），**没有做实时性/中断/DMA 验证**（没有 WCET 分析、没有中断延迟测量、没有 cache/内存带宽考虑），没有做过定点化（全部是 double 浮点，真实 DSP/MCU 上多半会走定点或单精度）。
5. **没做的**：没有做场景级 NETD 测试；没有黑体实物标定（没有采集过真实标定数据，没有处理过非均匀性随时间漂移、没有做过单点/两点/多点标定的工程权衡）；没有做图像质量的主观评价（没有观察者实验、没有 MDTD/MTF 之类的人因指标）；**没有做 LVDS / Camera Link 等真实探测器接口的电气层**（没有并串转换、没有均衡、没有眼图、没有时序余量分析）。BT.656 只做了光栅结构，没有做电气层与嵌入定时码。
6. **没有做硬件在环，没有做故障注入。**

因此这个仓库适合用来讨论"这条链路的每一步是怎么算的、指标怎么定义、参数怎么取舍"，**不适合**用来推断任何真实探测器、TEC 或 VCSEL 器件的性能。

## 踩过的坑

全部是开发过程中**真实出现并被测试或对账抓出来**的问题，按"现象 → 根因 → 修法"记录。

### 1. 阶跃响应超调量永远是 0.00 %

- **现象**：TEC 扫参时 20 组参数的超调量全是 `0.00 %`，`peak_K` 也全等于起始温度 25.0000。
- **根因**：指标代码里把"极值"写成了 `max(T)`。这个用例是**降温**（25 → −20 ℃），温度单调下降，永远不超过起点，所以超调恒为 0。
- **修法**：按**阶跃方向**取极值——`step < 0` 时取最小值算下冲，`step > 0` 时取最大值算超调，百分比都以阶跃幅度为基准。顺带发现同一个函数里 `bandwidth_K`（末段峰峰值）用 `tbuf[0]` 初始化，而这个值在"最后 20 % 窗口"之外，所以永远报 45 K 的假峰峰值；改成在窗口内初始化。

### 2. VCSEL 目标电流算出来是 4981 mA

- **现象**：`vcs_required_current(25 ℃)` 应该是约 6 mA，实际返回 4981 mA；三种补偿策略的扫温结果全是 99.4 % 偏差、电流全部顶到 15 mA 上限。
- **根因**：**单位写错**。斜率效率填成了 `1e-3 W/A`，但"1 mW 光功率每 mA 驱动电流" = 1 mW/mA = **1 W/A**（1e-3 W ÷ 1e-3 A = 1）。差三个数量级，目标电流自然炸掉。
- **修法**：`eta_ref = 1.0`，并且**加了一条回归断言**：`vcs_required_current(25 ℃) ≈ 5.98 mA`（容差 0.1 mA），以及"用这个电流驱动必须精确打到 5 mW"。单位错误这类问题靠读代码很难发现，靠一条带物理量的断言很容易。

### 3. APC 闭环发散成 180 % 极限环

- **现象**：闭环 APC 模式的最大功率偏差 180.4 %，比不补偿的 41 % 还差，功率在 0.02 mW 与 14.02 mW 之间来回跳。
- **根因**：外环积分增益取了 `1e6 A/(W·s)`，闭环时间常数 `τ = 1/(η·gain) = 1 µs`，而外环更新周期是 **10 µs**。**环路带宽比采样率还高**，等于每拍都过冲，必然振荡。
- **修法**：增益降到 `1000`，`τ = 1 ms`，是更新周期的 100 倍。教训很直接：采样率必须比闭环带宽高一个数量级以上，这条设计规则在代码里也必须成立。

### 4. 平台直方图均衡的"小平台极限"反了

- **现象**：单元测试断言"`plateau_frac → 0` 时平台均衡逼近线性拉伸"失败，实际 `map[0]` 差 126 个灰阶。
- **根因**：实现里写了 `if (mode == HEQ || t_d < 1.0) { t = SIZE_MAX; }`，本意是处理"平台低于一个 count"的退化情况，结果把**最小平台**当成了**无裁剪**——极限行为完全反了：`plateau_frac → 0` 变成了完全 HEQ。
- **修法**：平台下限钳到 1 count（`plateau → 0` 时直方图被削成近似均匀，映射自然趋向线性），HEQ 才走无裁剪分支。这条是**测试先失败、再去改实现**的典型：算法文档里写清的极限行为，正好是最容易被实现写反的地方。

### 5. 盲元替换"跑了 375 个像元，残差一个都没变"

- **现象**：仿真里 3×3 中值替换报告替换了 375 个像元，但替换前后的 MAE / RMSE / 最大值**完全相同**（262.45 → 262.45）。
- **根因**：两个 bug 叠在一起。(a) `main_sim.c` 声明了 `badpix_replace_cfg_t rc;` 却**忘了调用 `badpix_replace_cfg_default(&rc)`**，`min_valid` 是栈上垃圾值，绝大多数像元因为"有效邻居不足"被原样保留；(b) `n_replaced` 计的是**处理过**的标记像元数，不是**值真的被改过**的像元数，所以"替换了 375 个"这个报告把 (a) 掩盖了。
- **修法**：`n_replaced` 只在真正写入新值时递增（并在头文件里写清语义）；`main_sim.c` 补上默认值初始化。这个 bug 的可怕之处在于：**指标看起来"有数值"，只是前后一样**，如果不做替换前后的对账（`badpix_residual` 同时算 before/after）就会一直看不出来。

### 6. CI 里报"BT.656 结构校验不通过"

- **现象**：128×128 光栅 `counts ok = yes`，但 BT.656 参考光栅 `counts ok = NO`，而单独打印的时钟数明明是对的。
- **根因**：`active_pixel_clocks` 统计的是 **DE 有效的时钟数**，BT.656 预设是 2 时钟/像素，所以是 `720×576×2 = 829 440`；而校验代码拿它去和 `h_active × v_active = 414 720` 比。
- **修法**：期望值改为 `h_active × v_active × clocks_per_pixel`，并把字段注释改成"DE 有效时钟（像素数 × clocks_per_pixel）"以免再被误读。

### 7. "鲁棒性扫描失败"其实是执行器选小了

- **现象**：TEC 鲁棒性扫描里 Rth = 1.2 K/W 的三行全部 `settle = -1`（永不进入 ±0.1 K）、稳态误差 9 K、饱和时间 150 s。第一反应是"控制器鲁棒性不行"。
- **根因**：算一下就知道不是控制器的问题——把冷平台维持在比环境低 45 K，需要 `(Tamb − Tset)/Rth = 45/1.2 = 37.5 W`，而驱动器上限只有 30 W。Rth ≤ 45/30 = **1.5 K/W** 的工况**物理上不可达**，PID 再调也没用。
- **修法**：不算 bug，但是个教训——扫描表里补上了 `required_W` 这一列，让"是控制器不行还是执行器不够"一眼可辨。同理，第一版抗饱和测试用了 50 % 的野值比例去触发 `max_flagged_frac` 保护，结果永远触发不了：切比雪夫不等式规定超过 3σ 的样本比例上限约 1/9 ≈ 11 %，**单次遍历根本不可能标记超过 20 %**。改成 5 % 野值的双点分布才构造出真正的用例。

### 8. 工程环境上的几个坑（真踩过）

- **Windows 文本模式把 `0x1A` 当 EOF**：二进制数据（以及任何可能含 `0x1A` 的文本）一旦用 `"w"` 打开就会在 `0x1A` 处被静默截断。所以本项目**所有**文件写出都用 `"wb"`，包括纯文本 CSV，并且测试里专门写了一个含 `0x1A` 的字符串做往返校验。
- **GNU Make 3.80 没有 `$(shell mkdir -p)` 这类可用行为**：所以 Makefile 里**没有任何子目录规则**，每个目标一条命令直接编译成根目录下的可执行文件；`results/` 作为目录随仓库提交，编译/运行都不需要建目录。
- **Windows 上 `-o test_ir` 实际产出 `test_ir.exe`**：如果目标名不写 `.exe`，make 会认为目标不存在而每次都重编。Makefile 里用 `ifeq ($(OS),Windows_NT)` 同时修正目标名、`-o` 参数和运行前缀。
- **`make sim | head` 会让 CI 非 0 退出**：管道断开触发 SIGPIPE，程序是被信号杀掉的，不是执行失败。CI 里改成先重定向到文件再 `tail`。
- **`-std=c99` 下没有 `M_PI`**：严格 C99 隐藏了 POSIX 扩展的 `M_PI`，自己定义常量，不要靠 `_GNU_SOURCE` 绕。
- **`-Wall -Wextra -Werror` 会把测试里的"设了没用的变量"变成编译失败**：这其实是好事，但写测试时要注意每个变量都要真的被断言用到。

## 测试与 CI

`test/test_ir.c` 是一个**完全自包含**的自检程序，不依赖任何测试框架：宏 `CHECK` / `CHECK_NEAR` 累加计数并记录失败位置，有任何失败则 `return 1`，全部通过时最后一行为：

```
2747 checks passed
```

覆盖范围：RNG 确定性与分布、统计量与 NU 定义（含手算校验）、TEC 的死区/限幅/三种抗饱和的积分器行为与闭环指标、NUC 两点代数精确性（对纯线性像元外推 150 counts 仍精确到 1e-9）与死像元保护、盲元判据/裁剪/边界/保护阈值/中值与均值替换、AGC 的直方图守恒与两个极限行为与对比度指标、帧时序状态机与 BT.656 参考光栅、CRC 标准向量与全部单 bit 错误检出、VCSEL 器件模型/单位/三种补偿策略/内环阶跃/含噪 APC，以及各模块的**边界与异常输入**（NULL、零长、退化配置、超量程）。

CI（`.github/workflows/ci.yml`）：**ubuntu-latest + macos-latest × gcc + clang** 共 4 个作业，全部带 `-Werror -Wall -Wextra -ffp-contract=off`；另有独立的 **ASan + UBSan** 作业（`detect_leaks=1`、`halt_on_error=1`），既跑自检也跑端到端仿真。
